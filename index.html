01 / PROJECT OVERVIEW

「どこで、どのくらい危険なのか？」

出没場所・日時・危険度・解除状態をまとめて確認できるサービス

BACKGROUND

一覧だけでは
場所を把握しにくい

住所と投稿を地図マーカーにつなぎ、関心のある地域の状況を位置関係から理解できるよう設計しました。

APPROACH

閲覧から通報まで
ひとつの利用フロー

トップページで状況を確認し、地図で範囲を絞り込んだ後、詳細の閲覧や目撃情報の通報へ進みます。

VALUE

危険情報に加えて
解除状態も伝える

DANGER・WARNING・CAUTIONとCLEARを区別し、出没情報の状態を色と文字で伝えます。

主な利用者 日本の地域住民・訪問者・サービス管理者
このスライドでは開発意図を説明します。事故減少率や実際の利用者数など、検証していない成果の数値は提示しません。

03 / DESIGN LANGUAGE

温かみのある印象と、明確な危険表示。

CREAM#EEE5D1
INK#332D25
YELLOW#E3AC1F

プロジェクトのビジュアル表現

クリーム色の背景に濃い茶色の枠線、紙のカードを思わせる面と影。黄色は主な操作を、赤色は危険情報を強調します。

CLEAR

解除 危険の解除状態

08 / MAP & FILTER

ひとつの検索結果を、地図と一覧に。

① データを画面用に整理

/api/map/markersから取得した座標・住所・危険度・日付を、マーカーと一覧で使う形式に変換します。

② 選択条件で絞り込む

地域、開始日／終了日、4種類の危険度のチェック状態を比較します。CLEARも個別に選択できます。

地図ページの検索は、読み込み済みデータに対するクライアント側のフィルターです。サーバーのperiodオプションとは区別します。クマのアイコン、日本語地図、期間の初期値と未来の日付の制限も実演します。

13 / TROUBLESHOOTING

検索すると投稿が消える原因。

BEFORE

日付オブジェクトを文字列として処理

eventDate: {
  date: { year: 2026, month: 9, day: 10 }
}

String(eventDate)
// "[object Object]"

日付表示と文字列の期間比較が正しく機能せず、正常な投稿が検索結果から除外されました。

AFTER

画面で比較できる形式に正規化

normalizeEventDate(item.eventDate)
// "2026-09-10"

開始日 ≤ 出没日 ≤ 終了日
// 同じYYYY-MM-DD形式で比較

年・月・日を取り出し、月／日を2桁にそろえることで日付表示と検索を修正しました。

解決の流れ：画面の症状 → 実際のJSONを確認 → データ形式を整理 → 検索を再確認
実際に修正した事例です。Google MapsのMarker非推奨警告と日付フィルターの問題は別の原因でした。重要なのはAPIと画面の間で日付形式をそろえることです。
